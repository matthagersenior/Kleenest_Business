# Kleenest Data Room — Source of Truth

## Version precedence

Unless a newer document explicitly says otherwise, use this precedence:

1. **Current v10 target-specific material** when discussing the exact target it was created for.
2. **Current v9 business-plan / finance / outreach material** for company-wide strategy, pricing, forecasts, market framing, and operating assumptions.
3. **Current normalized market-evidence material** for claims that require cited evidence.
4. **Current validation / opportunity-readiness material** for process, interview design, proof systems, diligence readiness, and meeting discipline.
5. **v8 and earlier documents** as historical context only.
6. **Early sales-ready HTML / one-page pitch / prototype lineage** as product and commercial history only.

## Claim rules

### Never convert these into traction automatically
- ingested location records,
- imported businesses,
- seeded/demo accounts,
- source records,
- app features,
- QR codes created but not used,
- outreach sent but not answered.

### Traction requires evidence such as
- active non-demo users,
- repeat usage,
- verified observations,
- real check-ins,
- participating pilot businesses,
- signed/confirmed pilots,
- willingness-to-pay evidence,
- revenue,
- renewals or expansion.

### Partner naming
Do not describe an organization as a partner, customer, participant, sponsor, or endorser without explicit evidence that supports the exact label.

### Accessibility
Do not describe community-observed accessibility attributes as certified unless backed by an authoritative certification/source.

### Competitor and market facts
Historical research snapshots must be reverified before public use if the claim can change over time.

## Conflict handling

When two sources disagree:

1. Prefer the higher-precedence source.
2. Preserve the older source in the archive.
3. Document the conflict if it affects pricing, forecasts, market size, legal claims, customer claims, or fundraising materials.
4. Never silently merge incompatible assumptions.

## Current-vs-historical indicator

Every newly added data-room document should clearly indicate whether it is:
- **Current**
- **Current process/reference**
- **Historical**
- **External reference**
- **Source-only / binary original**
